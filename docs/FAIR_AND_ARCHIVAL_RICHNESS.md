# FAIR and archival richness

This document maps the repository to FAIR research-object principles and records the remaining preservation gaps before the first DOI-bearing release.

## Findable

Implemented:

- stable public GitHub repository;
- ORCID-linked creator metadata;
- `CITATION.cff`;
- CodeMeta;
- Zenodo metadata draft;
- DataCite metadata draft;
- structured keywords and subject labels;
- machine-readable artifact registry;
- claim–evidence matrix.

Pending:

- Zenodo version DOI and concept DOI;
- arXiv identifier;
- Software Heritage persistent identifier.

## Accessible

Implemented:

- public source, paper, evidence data, and documentation;
- explicit open licenses;
- standard UTF-8 text, CSV, and JSON formats;
- PDF and LaTeX manuscript forms;
- downloadable reviewer bundle generated by CI.

Pending:

- frozen tagged release;
- archival mirror independent of GitHub.

## Interoperable

Implemented:

- CSV and JSON evidence tables;
- CFF, CodeMeta, RO-Crate, SPDX, and DataCite-oriented metadata;
- exact rational strings and integer fields for theorem-critical data;
- explicit artifact roles and evidence classes;
- standard ORCID and repository URLs.

Pending:

- final DOI insertion across all metadata records;
- optional formal schema publication for validation targets and claim registry.

## Reusable

Implemented:

- split licenses for software and scholarly materials;
- exact environment and installation instructions;
- deterministic verification;
- CI for two Python versions;
- clean-room replication protocol;
- reviewer declaration and conflict-of-interest policy;
- machine-readable expected-output table.

Pending:

- independent external replication;
- two independent mathematical referee reports;
- frozen v1.0.0 manifest and SHA-256 ledger.

## Preservation stack for v1.0.0

The intended archival stack is:

1. immutable Git tag `v1.0.0`;
2. GitHub Release;
3. Zenodo version DOI and concept DOI;
4. Software Heritage archival snapshot and SWHID;
5. arXiv manuscript identifier;
6. final `MANIFEST.json` and `SHA256SUMS.txt` committed in the archival tag;
7. provenance links in CFF, CodeMeta, RO-Crate, DataCite draft, README, and manuscript.

## Archival-quality boundary

Metadata richness can be completed internally. External mathematical validity cannot. The DOI gate therefore remains blocked until the validation policy in `docs/validation/VALIDATION_STATUS.md` is satisfied.
